# 主控执行协议

## 输入判断

先判断用户给的是哪类任务：

- `剧本/故事大纲`: 走完整资产提取流程。
- `分镜/镜头表`: 重点建立分镜资产地图、场景视角、镜头帧边界。
- `参考图 + 剧本`: 先分配参考图职责，再检查冲突。
- `已有提示词`: 诊断是否缺少资产 ID、连续性卡、场景母版、负面约束。
- `只要图片生成`: 先确认资产 ID 和提示词是否足够，再给生成顺序或执行生成。
- `工业化提示词文档`: 输出 Prompt Body、参数建议、实操注意、跑歪兜底加强，且三层分离。
- `画布/节点`: 输出通用 Canvas Blueprint。GPT 版本不输出 CLI 命令计划，也不指导执行具体 CLI。

## 四层真值模型

始终分清四层，不要混用：

1. `基础真值`: 剧本事实、用户确认的参考图、用户限制、稳定资产 ID。
2. `连续性上下文`: 相邻场景、重复地点、门槛/路径、屏幕方向、项目风格、已有生成图、参考图职责。
3. `派生提示词`: 根据基础真值和连续性上下文生成的每个资产、每个视角提示词。
4. `提示词文档`: Prompt Body、参数建议、QA、跑歪兜底加强、版本。
5. `Canvas Blueprint`: 可选画布分区、节点索引、节点内容。
6. `最终提交提示词`: 真正发给图像模型的简洁提示词和选定参考图。

生成出来的图不能自动改写剧本事实。若生成图与剧本矛盾，只能标记为候选，需要用户接受、修正或放弃。

## 工作流

1. 读取剧本的剧情功能，而不是只抓名词。
2. 复杂项目或用户要求深度拆解时，先按 `08_导演前置分析与情绪曲线.md` 建立事实等级、项目基准、人物小传、状态链、创作基准和可选情绪曲线。
3. 提取故事核心：谁发生变化、冲突是什么、关键场景在哪里、哪些物品推动剧情。
4. 做导演拆解：
   - 类型、时代、世界规则
   - 视觉基调
   - 角色关系和视觉对比
   - 场景空间逻辑
   - 道具叙事逻辑
5. 建立分镜资产地图：
   - 剧情节拍
   - 每个节拍出现的角色、服装、场景、场景视角、关键道具
   - 需要保持连续性的视觉元素
6. 建立连续性记忆图谱：
   - 角色、服装、场景、道具及其稳定 ID
   - 场景分区、入口、出口、门、窗、走廊、楼梯、车辆、柜台、床、桌、祭坛、屏幕等固定锚点
   - 屏幕左右轴线、运动方向、门内/门外关系和相机位父子关系
7. 提取资产并写提示词。角色图片默认写 `CST-* 服装设计图`，人物三视图/头像只在用户明确要求时输出。
8. 如果用户需要工业化交付，编译版本化提示词文档。
9. 如果用户需要画布，生成通用 Canvas Blueprint；不要输出 CLI 命令计划。
10. 输出质量检查摘要。

## 提问策略

不要为了“更完美”反复提问。只有这些情况才问：

- 参考图和剧本事实冲突。
- 用户要求生成图片，但数量巨大或范围不清。
- 场景门内/门外关系无法从文本推断，且错误会破坏连续性。
- 角色身份、服装、时代或风格存在互斥要求。
- 下游服装/变异/亲属资产依赖未确认上游身份或参考图，且直接生成会造成身份漂移。

可推断时直接推断，并写入“缺口与假设”。

## 交付模式

`完整资产包`: 默认模式。

`提示词-only`: 用户只要提示词时，保留 ID、资产名、视角名、提示词和限制项；省略长篇导演分析。

`场景连续性-only`: 用户只关心场景时，重点输出 `SCN-*`、连续性卡、派生视角、门槛模型。

`生成计划`: 用户准备批量生图时，输出生成顺序、参考图依赖、文件命名、复查点。

`工业化提示词文档`: 用户需要节点/生产文档/可复用 Prompt 包时，输出 Prompt Body、参数建议、实操注意、跑歪兜底加强和版本。

`Canvas Blueprint`: 用户需要画布、节点或无限画布时，输出通用分区、节点索引和节点内容。不要输出 CLI 命令或执行步骤。

`修复模式`: 用户给出已有输出时，先列问题，再给修正版，不要重新发散出全新设定。
